# 생활비·자동차·대출 계산기 MVP 설계 명세

## 1. 제품 정의

### 목표

한국 사용자가 자동차를 구매·운행하거나 돈을 빌리고 모을 때 드는 비용을, 로그인이나 개인정보 입력 없이 빠르고 이해할 수 있게 계산하는 광고 기반 웹 도구를 만든다.

### 한 문장 가치 제안

차를 사고 유지하고, 돈을 빌리고 모을 때 드는 실제 비용을 한눈에 계산한다.

### 사용자와 상황

- 차량 구매 또는 교체를 검토하는 사용자
- 월별 차량 유지비와 유류비를 점검하려는 운전자
- 대출 금리·기간·상환 방식별 월 납입액과 총이자를 비교하려는 사용자
- 예적금·복리와 월 생활비를 간단하게 시뮬레이션하려는 사용자

### 성공 정의

- 처음 방문한 사용자가 설명 없이 한 개의 계산을 완료할 수 있다.
- 각 결과에는 산식, 입력 가정, 단위, 반올림 기준, 한계가 표시된다.
- 계산값은 서버·분석 도구·광고 플랫폼으로 전송하거나 저장하지 않는다.
- 광고를 도입한 뒤에도 입력과 결과 확인을 방해하지 않고 Core Web Vitals 목표를 유지한다.

## 2. 범위

### P0 공개 계산기

| 경로 | 계산기 | 핵심 결과 |
| --- | --- | --- |
| `/car/maintenance-cost/` | 자동차 유지비 계산기 | 연간·월간·1km당 총비용과 비용 항목별 비중 |
| `/car/fuel-cost/` | 유류비·연비 계산기 | 주행거리 기준 연료 사용량과 유류비 |
| `/car/ev-charging-cost/` | 전기차 충전비 계산기 | 충전량과 전기요금 기준 월간·연간 충전비 |
| `/car/purchase-cost/` | 차량 구매 총비용 계산기 | 초기 현금, 할부 총납입액, 자금 조달 차이 |
| `/car/installment/` | 자동차 할부 계산기 | 월 납입액, 총이자, 상환표 |
| `/finance/loan-interest/` | 대출 이자 계산기 | 단리 이자와 기간별 이자 추정값 |
| `/finance/loan-repayment/` | 대출 상환 방식 비교 계산기 | 원리금균등·원금균등·만기일시의 월 납입액과 총이자 비교 |
| `/finance/compound-interest/` | 예적금·복리 계산기 | 납입원금, 이자, 만기 예상액 |
| `/life/monthly-budget/` | 월 생활비 예산 계산기 | 수입 대비 고정비·변동비·저축 여력 |

### P1 후보

- 중도상환 이자 절감 계산기
- 자동차 리스·할부 비교 계산기
- 내연기관·전기차 유지비 비교 계산기
- 여행·장거리 운전 비용 계산기
- 전세·월세·주택 대출 관련 계산기

### 이번 단계의 제외 범위

- 금융상품 추천, 대출 가능 금액 판단, 신용 평가
- 자동차 보험료·취득세·공채 등 외부 기준값을 자동으로 추정하는 기능
- 로그인, 회원 정보, 계산 이력 서버 저장, 결제
- AI 상담, 챗봇, 네이티브 앱, 다국어, 초기 CMS
- 대출·세무·법률·투자 자문으로 해석될 수 있는 문구

## 3. 제품 원칙

1. 계산부터 보여 준다. 첫 화면에서 제목, 필요한 입력값, 계산 버튼, 결과 영역의 위치를 모두 확인할 수 있어야 한다.
2. 사용자가 이해할 수 있는 수치만 사용한다. 외부 데이터나 추정 계수는 P0에 넣지 않고, 필요한 비용과 금리는 사용자가 직접 입력한다.
3. 결과의 근거를 숨기지 않는다. 공식, 가정, 반올림, 미포함 항목, 참고용 고지를 결과 바로 아래에 둔다.
4. 입력값은 개인 데이터다. URL, 서버 로그, 분석 이벤트, 광고 요청에 입력값을 포함하지 않는다.
5. 광고는 계산 후에만 노출한다. 광고는 입력 폼·계산 버튼·결과 복사 버튼·오류 메시지와 시각적으로 분리한다.
6. 각 계산기는 독립적으로 쓸 수 있어야 한다. 동시에 같은 맥락의 다음 계산기로 자연스럽게 이어져야 한다.

## 4. 정보 구조와 사용자 흐름

```text
홈
├── 자동차
│   ├── 유지비
│   ├── 유류비·연비
│   ├── 전기차 충전비
│   ├── 구매 총비용
│   └── 할부
├── 금융
│   ├── 대출 이자
│   ├── 상환 방식 비교
│   └── 예적금·복리
└── 생활비
    └── 월 생활비 예산
```

### 기본 흐름

1. 사용자는 홈의 검색 또는 자동차·금융·생활비 카테고리에서 계산기를 연다.
2. 계산기 페이지에서 명시된 단위와 기본 예시를 보고 입력값을 넣는다.
3. 브라우저에서 즉시 계산하고 결과·산식·주의사항·관련 도구를 확인한다.
4. 필요하면 결과를 텍스트로 복사하거나 현재 입력값을 포함하지 않는 페이지 링크를 공유한다.
5. 결과 아래의 문맥형 관련 도구를 선택한다.

### 관련 도구 규칙

- 자동차 유지비 → 유류비·연비, 전기차 충전비, 차량 구매 총비용
- 차량 구매 총비용 → 자동차 할부, 자동차 유지비, 대출 상환 방식 비교
- 자동차 할부 → 대출 상환 방식 비교, 대출 이자
- 대출 상환 방식 비교 → 대출 이자, 예적금·복리
- 월 생활비 예산 → 자동차 유지비, 예적금·복리

관련 도구는 각 페이지에 최대 네 개만 노출한다. 무관한 도구를 체류 시간 목적만으로 추천하지 않는다.

## 5. 계산기 공통 경험

### 화면 순서

1. 브레드크럼
2. H1과 한 문장 설명
3. 입력 폼
4. 계산 버튼과 초기화 버튼
5. 결과 패널
6. 산식과 예시
7. 입력 범위·미포함 항목·참고용 안내
8. 출처와 마지막 검토일
9. 관련 계산기
10. 광고 슬롯

### 입력과 결과 규칙

- 모든 입력에는 눈에 보이는 라벨, 단위, 허용 범위, 예시가 있다.
- 금액은 원화 기준 정수로 처리하며 표시 시 천 단위 구분 기호를 사용한다.
- 비율은 퍼센트 단위로 입력하고 내부 계산에서는 소수 비율로 변환한다.
- 중간 계산은 이진 부동소수점이 아닌 십진 정밀도 방식으로 처리한다.
- 결과 표시는 각 계산기의 정의된 시점에만 반올림한다.
- 빈 값, 음수, 0으로 나누는 값, 허용 범위 밖의 값은 해당 필드 바로 아래에 오류로 표시한다.
- 계산 결과가 바뀌면 스크린리더가 한 번만 읽도록 결과 영역을 갱신한다.
- 모바일의 숫자 입력은 적절한 숫자 키패드를 호출한다.

### 공유와 복사

- 복사는 결과 요약, 입력 가정, 참고용 고지를 텍스트로 생성한다.
- 공유 링크는 계산기 기본 URL만 포함한다. 입력값을 URL 파라미터에 넣지 않는다.
- 입력값 보존 기능은 P0에 넣지 않는다.

## 6. 계산 명세

### 자동차 유지비

입력:

- 연간 주행거리
- 연비 또는 전비
- 연료·충전 단가
- 연간 보험료
- 연간 자동차세
- 연간 정비·소모품 비용
- 연간 주차·통행료 및 기타 비용

출력:

- 연간 총 유지비
- 월 평균 유지비
- 1km당 비용
- 연료·충전비, 보험료, 세금, 정비비, 기타 비용의 항목별 표와 비중

규칙:

- 연료·충전비는 `연간 주행거리 ÷ 연비 또는 전비 × 단가`로 계산한다.
- 사용자가 선택한 동력원에 맞지 않는 입력 필드는 숨기고 계산에서 제외한다.
- 감가상각, 대출 이자, 사고 수리비는 기본값으로 포함하지 않으며 미포함 항목으로 고지한다.

### 유류비·연비

입력:

- 주행거리
- 연비(km/L)
- 유종 단가(원/L)

출력:

- 예상 연료 사용량
- 예상 유류비
- 1km당 유류비

규칙:

- `주행거리 ÷ 연비 × 유종 단가`를 사용한다.
- 연비는 0보다 커야 한다.

### 전기차 충전비

입력:

- 주행거리
- 전비(km/kWh)
- 충전 단가(원/kWh)

출력:

- 예상 전력 사용량
- 예상 충전비
- 1km당 충전비

규칙:

- `주행거리 ÷ 전비 × 충전 단가`를 사용한다.
- 실제 충전 손실, 계절·주행 습관 차이, 충전 사업자별 요금은 결과에 포함하지 않는다고 고지한다.

### 차량 구매 총비용

입력:

- 차량 가격
- 선택 비용(탁송·등록·옵션 등 사용자가 합산 입력)
- 초기 현금(계약금·선납금 포함)
- 할부 원금
- 연 이자율
- 상환 기간

출력:

- 초기 현금 필요액
- 할부 월 납입액
- 할부 총이자
- 차량 가격·선택 비용·초기 현금·할부 원금·총 납입액·자금 조달 차이의 요약

규칙:

- 취득세·보험료·공채 등은 자동 계산하지 않는다. 사용자가 선택 비용에 넣은 금액만 반영한다.
- 자금 조달 차이는 `차량 가격 + 선택 비용 - 초기 현금 - 할부 원금`으로 계산한다. 양수면 아직 마련하지 않은 금액, 음수면 입력한 조달 금액이 구매 금액보다 큰 상태로 표시한다.
- 할부 계산은 원리금균등을 기본으로 하고, 상환 방식은 자동차 할부 계산기에서 자세히 비교하도록 연결한다.

### 자동차 할부

입력:

- 할부 원금
- 연 이자율
- 상환 기간(개월)
- 상환 방식

출력:

- 월 납입액 또는 첫 달·마지막 달 납입액
- 총 납입액
- 총이자
- 월별 원금·이자·잔액 상환표

상환 방식:

- 원리금균등
- 원금균등
- 만기일시

### 대출 이자

입력:

- 대출 원금
- 연 이자율
- 이용 기간(일·개월·년 중 하나)

출력:

- 단리 기준 예상 이자
- 원금 포함 만기 예상액

규칙:

- 일 단위 계산은 사용자가 선택한 연 기준 일수 365일 또는 366일을 명시해 계산한다.
- 실제 금융기관의 일수 계산 방식, 우대금리, 연체이자, 중도상환 수수료는 반영하지 않는다고 고지한다.

### 대출 상환 방식 비교

입력:

- 대출 원금
- 연 이자율
- 상환 기간(개월)

출력:

- 원리금균등·원금균등·만기일시의 총이자, 총납입액, 대표 월 납입액 비교표
- 각 방식별 상환표 링크 또는 펼침 영역

규칙:

- 월 이자율은 `연 이자율 ÷ 12`로 계산한다.
- 원리금균등 월 납입액은 `원금 × 월 이자율 × (1 + 월 이자율)^개월 수 ÷ ((1 + 월 이자율)^개월 수 - 1)`로 산출한다.
- 이자율이 0%인 경우에는 원금을 개월 수로 나누고, 0으로 나누지 않는다.
- 만기일시는 매월 이자만 납부하고 마지막 달에 원금을 납부하는 것으로 정의한다.

### 예적금·복리

입력:

- 초기 원금
- 매월 납입액
- 연 이자율
- 기간(개월)
- 이자 계산 주기

출력:

- 총 납입원금
- 예상 이자
- 만기 예상액
- 월별 누적 추이 표

규칙:

- 세전 결과가 기본이며, 세후 결과를 표시하려면 세율을 사용자가 직접 입력하게 한다.
- 금융기관별 우대 조건, 중도해지, 이자 지급일은 반영하지 않는다.

### 월 생활비 예산

입력:

- 월 순수입
- 주거비
- 자동차비
- 식비
- 통신·구독비
- 보험·의료비
- 기타 고정비
- 기타 변동비
- 목표 저축액

출력:

- 지출 총액
- 수입 대비 지출 비율
- 목표 저축액 반영 후 잔여 금액
- 항목별 비중

규칙:

- 사용자의 재무 상태를 평가하거나 소비 습관에 대해 규범적 판단을 하지 않는다.
- 자동차비에는 자동차 유지비 계산기 결과를 수동으로 입력하도록 안내한다.

## 7. 기술 아키텍처

### 선택

Next.js App Router와 TypeScript를 사용한다. 공개 페이지는 정적 생성 우선으로 제공하고, 계산 폼과 결과 갱신만 클라이언트에서 동작시킨다.

### 구성 요소

| 단위 | 책임 |
| --- | --- |
| 계산 엔진 | 금액·비율·기간을 십진 정밀도로 계산하고 공통 반올림을 제공 |
| 계산기 정의 | 입력값, 검증 규칙, 계산 함수, 결과 형식, SEO 메타데이터, 관련 도구를 등록 |
| 계산기 폼 | 라벨·단위·오류·예시·초기화·숫자 입력을 공통으로 제공 |
| 결과 패널 | 요약, 세부 표, 산식, 복사, 접근성 알림을 제공 |
| 콘텐츠 블록 | 공식 설명, 예시, 한계, 출처, 검토일을 서버 렌더링 |
| SEO 계층 | 제목, 설명, canonical, Open Graph, JSON-LD, sitemap, robots를 생성 |
| 분석 계층 | 익명 사용 흐름만 수집하고 계산 입력값은 제외 |
| 광고 배치 계층 | 승인 후 허용된 위치에만 고정 크기 슬롯을 렌더링 |

### 데이터 경계

- P0에는 데이터베이스와 외부 금융·자동차 API를 사용하지 않는다.
- 계산 정의·콘텐츠·출처·검토일은 버전 관리되는 로컬 파일에 둔다.
- 금액·금리·거리·차종·월수입 등 사용자 입력은 브라우저 메모리에만 둔다.
- 분석 이벤트에는 계산기 경로, 완료 여부, 오류 종류, 관련 링크 클릭 여부만 넣는다.

## 8. SEO·콘텐츠·신뢰

### 공개 페이지 요건

- 한 검색 의도에 하나의 대표 URL을 사용한다.
- 각 페이지는 고유 H1, 설명, 공식, 사례, 한계, 출처, 검토일을 가진다.
- 홈페이지·카테고리·관련 도구에서 모든 계산기 페이지에 도달할 수 있게 한다.
- URL은 소문자 영문 하이픈 경로와 일관된 trailing slash를 사용한다.
- canonical, XML sitemap, robots.txt, Open Graph, BreadcrumbList를 제공한다.
- WebSite, WebPage, BreadcrumbList 외 구조화 데이터는 화면에서 사실로 확인 가능한 경우에만 사용한다.

### 콘텐츠 품질 게이트

- 이름과 숫자만 바꾼 템플릿 페이지를 만들지 않는다.
- 페이지마다 실제 계산 목적에 맞는 사례와 미포함 조건을 작성한다.
- P0 모든 페이지는 공개 전 사람이 산식·출처·문구를 검토한다.
- 금융·자동차 비용 결과에는 "참고용 계산"과 "실제 계약·청구 금액과 다를 수 있음"을 명시한다.
- 운영자 소개, 편집 원칙, 수정 요청, 문의, 개인정보처리방침, 이용약관을 공개한다.

## 9. 광고와 개인정보

### 광고 도입 순서

1. 광고 없는 상태로 제한 출시하여 정확성·사용성·성능 기준선을 수집한다.
2. 정책 페이지·운영자 정보·문의 채널을 갖춘 뒤 AdSense를 신청한다.
3. 첫 광고는 결과·핵심 설명 이후에 한 개의 수동 슬롯으로 시작한다.
4. 모바일과 데스크톱에서 실제 광고가 채워진 상태를 검증한다.
5. 성능과 계산 완료율이 유지될 때만 두 번째 슬롯을 실험한다.

### 금지 위치

- H1과 입력 폼 사이
- 계산 버튼 주변
- 숫자 키패드 또는 필드 오류 메시지 주변
- 결과 요약과 결과 복사 버튼 주변
- 모바일 화면을 가리는 팝업·전면 광고

### 레이아웃 안정성

- 광고 슬롯은 로드 전에도 고정된 공간을 확보한다.
- 자동 광고는 P0에서 사용하지 않는다.
- 광고의 라벨과 경계는 제품 기능과 명확히 구분한다.

### 개인정보

- 계산값은 서버로 전송하거나 저장하지 않는다.
- 광고·분석 쿠키의 처리 사실은 개인정보처리방침에서 계산값 처리와 분리해 설명한다.
- 개인화 광고 또는 해당 지역에서 요구되는 동의는 적용 법령과 광고 플랫폼 요구사항을 확인한 뒤 도입한다.

## 10. 접근성·성능 기준

### 접근성

- 기본 본문 글자 크기 16px 이상
- 텍스트 대비 4.5:1 이상
- 모든 입력에 연결된 라벨과 단위 제공
- 모든 기능을 키보드로 사용할 수 있고 포커스가 보임
- 터치 대상 최소 44px, 인접 대상 간 충분한 간격 확보
- 오류는 해당 필드와 연결하고 결과는 한 번만 알림
- 애니메이션은 기능 전달용으로만 사용하고 reduced-motion을 준수

### 성능

- 핵심 콘텐츠와 SEO 메타데이터를 초기 HTML로 제공
- 계산 로직은 즉시 실행돼야 하며 네트워크 요청에 의존하지 않음
- 이미지·폰트·서드파티 스크립트를 최소화
- 실제 사용자 p75 기준 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하를 목표로 함

## 11. 검증 전략

### 자동 검증

- 각 계산 공식의 정상·경계·오류 입력 단위 테스트
- 원리금균등·원금균등·만기일시 상환표의 합계·잔액 검증
- 0% 금리, 1개월 기간, 큰 금액, 소수 이자율, 빈 값, 음수, 0 나누기 회귀 테스트
- 모든 경로의 metadata, canonical, sitemap, JSON-LD, 내부 링크 검증
- 숫자 입력·결과 알림·키보드 탐색·모바일 화면 회귀 테스트

### 수동 검증

- 계산기별 결과를 독립적인 계산표 또는 공인·신뢰 출처의 예시와 교차 확인
- 375px, 768px, 1024px, 1440px에서 입력·결과·광고 슬롯을 확인
- 광고 없는 상태와 실제 광고가 채워진 상태 모두에서 계산 완료 흐름을 점검
- Lighthouse와 실제 사용자 데이터로 성능·접근성·SEO를 점검

### 출시 차단 조건

- 금액·이자·잔액 계산의 불일치
- 사용자의 입력값이 서버·분석·URL에 노출되는 동작
- 공개 페이지의 noindex, 잘못된 canonical, 깨진 sitemap, 고아 페이지
- 모바일에서 광고·팝업이 입력 또는 결과를 가리는 동작
- 심각한 접근성 오류 또는 CLS 0.1 초과

## 12. 아직 확정하지 않은 운영 결정

- 서비스의 최종 브랜드명과 도메인
- `bongworks` 저장소의 정확한 이름과 공개 여부
- 배포 플랫폼과 비용 한도
- 개인정보처리방침의 실제 운영자 연락처
- AdSense 계정·동의 관리 도구 도입 시점

이 결정들은 제품 기능과 분리돼 있다. 최종 브랜드·도메인을 확정하기 전에도 계산기 명세와 구현 계획은 진행할 수 있지만, 저장소 생성·배포·정식 메타데이터에는 확정값이 필요하다.
